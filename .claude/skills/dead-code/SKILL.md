# 2단계: 불필요한 코드 제거 (작동 변경 없음)

## 목표
IDE 또는 정적 분석 관점에서 "미사용"으로 판단되는 항목을 제거한다. **작동이 바뀌지 않아야 한다.**

## 대상 범위
`src/main/java/gift/` 아래의 모든 `.java` 파일

## 탐색 항목

아래 카테고리를 순서대로 전체 대상 범위에서 탐색한다.

### 1. 미사용 의존성 (필드/생성자 주입)
- 클래스에 주입된 필드(Repository, Service, Client 등)가 해당 클래스 내 어디에서도 사용되지 않는 경우
- 필드 선언, 생성자 파라미터, 생성자 대입문, import문을 모두 제거한다
- 탐색 방법: 각 클래스의 필드 목록을 확인하고, 해당 필드가 생성자 외에 참조되는 곳이 있는지 Grep으로 검증

### 2. 미사용 메서드
- 정의만 있고 프로젝트 어디에서도 호출되지 않는 public/private 메서드
- JPA 엔티티의 getter/setter는 직렬화·프레임워크 사용 가능성이 있으므로 신중히 판단

### 3. 미사용 import문
- 사용되지 않는 import 제거

### 4. 불필요한 주석
- 메서드명·변수명으로 자명한 내용을 반복하는 주석

### 5. 간소화 가능한 코드
- `Collectors.toList()` → `.toList()` (Java 16+) 등 최신 API로 대체 가능한 패턴

## 제외 항목 (삭제하지 않음)
- JPA `protected` 기본 생성자 — 프레임워크가 요구
- 중복 코드(인증 체크, null 체크 패턴) — 3단계 서비스 계층 추출에서 해소
- `@Autowired` 제거 — 1단계 스타일 정리에서 처리

## 작업 방식
1. 탐색 항목 카테고리 순서대로 대상 범위 전체를 스캔하여 미사용 코드를 발견한다
2. 발견된 항목과 삭제 근거를 사용자에게 보고한다
3. 승인 후 한 항목씩 제거한다
4. 각 항목 제거 후 `./gradlew build`로 빌드가 깨지지 않는지 확인한다
5. 항목별로 커밋 메시지를 제안한다

## 제약
- 사용 중인 코드를 삭제하지 않는다
- 메서드 시그니처, 로직, 반환값을 변경하지 않는다
- 새로운 클래스나 메서드를 추가하지 않는다
- 테스트를 비활성화하거나 삭제하지 않는다
